# 설치와 Supabase 설정

새로 개발 환경을 만들거나 Supabase 프로젝트를 처음 만들 때 보는 문서.
평소 DB 변경과 배포는 CI 가 한다. ([테스트 서버와 배포](테스트서버와배포.md))

## 개발 환경

- Flutter stable (3.47 이상), Chrome
- Node.js 20 이상 (DB 테스트, Supabase CLI)

```sh
flutter pub get
npm install        # 선택: 루트 package.json 의 Supabase CLI (npx supabase 로 실행)
```

## 1. 프로젝트 만들기

[supabase.com](https://supabase.com) 에서 새 프로젝트를 만든다. (Region: Northeast Asia (Seoul) 권장)

## 2. Auth 설정 (중요)

Dashboard > **Authentication** 에서

| 설정 | 값 | 이유 |
| --- | --- | --- |
| Allow new users to sign up | **켬** | 회원이 앱에서 직접 가입한다. 가입만으로는 아무 데이터도 볼 수 없고 관리자 승인이 필요하다. |
| Email provider | 켬 | 학번을 가상 이메일로 매핑해 사용 |
| Confirm email | **끔** | `@ccc.local` 은 가상 이메일이라 확인 메일을 받을 수 없다. 켜 두면 가입 후 로그인이 안 된다. |
| Minimum password length | 8 | 앱의 비밀번호 규칙과 맞춤 |

## 3. 스키마 / RLS 적용

새 프로젝트를 처음 만들 때만 직접 적용한다. 이후에는 CI 가 새 마이그레이션만 적용한다.

```sh
npx supabase db push --db-url "<Session pooler 접속 문자열>"
```

- 접속 문자열은 [CLI 로 적용할 때](테스트서버와배포.md#cli-로-적용할-때) 참고.
- SQL Editor 로 적용한다면 [supabase/migrations/](../../supabase/migrations/) 의 파일을 **이름 순서대로** 하나씩 실행한다.
  이 경우 CI 를 쓰기 전에 [적용 이력 맞추기](테스트서버와배포.md#적용-이력-맞추기-sql-editor-로-적용해-온-db)를 한다.
- `20261009000000_campuses.sql` 은 회원이 있는 DB 라면 학번 20250133(KAIST) 계정이 있어야 적용된다. (총괄 관리자로 지정)
- 각 마이그레이션이 무엇을 바꾸는지는 파일 맨 위 주석에 있다.

## 4. Edge Function (비밀번호 초기화 / 가입 거절)

[supabase/functions/admin-members/index.ts](../../supabase/functions/admin-members/index.ts) 를 배포하고 기본 비밀번호를 secret 으로 설정한다.
호출자의 토큰과 관리자 여부는 함수 안에서 직접 검증하므로 JWT 검증을 끈다. ([supabase/config.toml](../../supabase/config.toml) 의 `verify_jwt = false`)
배포는 평소 CI 가 한다. `DEFAULT_PASSWORD` 만 프로젝트마다 한 번 설정한다.

```sh
npx supabase login
npx supabase secrets set DEFAULT_PASSWORD='영문숫자8자이상' --project-ref <프로젝트 ref>
npx supabase functions deploy admin-members --project-ref <프로젝트 ref>   # 직접 배포할 때만
```

CLI 없이: Dashboard > **Edge Functions** > Deploy a new function > Via Editor 에서 이름을 `admin-members` 로 하고
index.ts 내용을 붙여넣어 배포한 뒤, 함수 설정에서 **Verify JWT** 를 끄고 **Edge Functions > Secrets** 에 `DEFAULT_PASSWORD` 를 추가한다.

## 5. 앱에 접속 정보 넣기

- **Project URL**: 프로젝트 상단 **Connect** 버튼, 또는 Project Settings > **Data API**.
  대시보드 주소 `.../project/<ref>` 의 ref 로 `https://<ref>.supabase.co` 를 만들어도 된다.
- **publishable key**(`sb_publishable_...`, 구 anon key): Project Settings > **API Keys**

`env.example.json` 을 `env.json` 으로 복사한 뒤 채운다. `env.json` 은 git 에 올라가지 않는다.
테스트 서버는 `env.staging.example.json` → `env.staging.json`. ([테스트 서버](테스트서버와배포.md#테스트-서버-staging))

```json
{
  "SUPABASE_URL": "https://xxxx.supabase.co",
  "SUPABASE_PUBLISHABLE_KEY": "sb_publishable_..."
}
```

> publishable 키는 브라우저에 노출되는 공개 키다. 실제 권한은 RLS 가 강제한다.
> **secret / service_role 키는 절대 앱이나 env.json 에 넣지 않는다.** (Edge Function 에서만 사용)

## 6. 최초 총괄 관리자 지정

1. 앱에서 **가입하기**로 본인 계정을 만든다. (승인 대기 화면이 나오면 정상)
2. [supabase/bootstrap_admin.sql](../../supabase/bootstrap_admin.sql) 의 학번 / 캠퍼스를 바꿔 SQL Editor 에서 실행
3. 승인 대기 화면에서 **승인 여부 다시 확인**

이후 캠퍼스 추가와 캠퍼스 관리자 지정은 앱에서 한다. ([총괄 관리자 사용법](../사용법-총괄관리자.md))

## 7. 가입 신청 알림 (웹 푸시)

새 가입(승인 대기 프로필)이 생기면 DB 트리거가 `pg_net` 으로 Edge Function [push](../../supabase/functions/push/index.ts) 를 부르고,
함수가 그 캠퍼스의 캠퍼스 관리자와 총괄 관리자 중 **설정 → 가입 신청 알림**을 켠 기기로 웹 푸시를 보낸다.
마이그레이션 `20261016000000_signup_push.sql` 과 함수 배포는 CI 가 한다. 아래 secret 만 프로젝트마다 한 번 설정한다.
설정하지 않으면 알림만 가지 않고 가입은 정상이다.

1. VAPID 키를 만든다. (운영 / 테스트 서버 따로)

   ```sh
   npx web-push generate-vapid-keys
   ```

2. 함수 secret. `PUSH_WEBHOOK_SECRET` 은 임의의 긴 문자열 (예: `openssl rand -hex 32`)

   ```sh
   npx supabase secrets set --project-ref <프로젝트 ref>      VAPID_PUBLIC_KEY='<Public Key>' VAPID_PRIVATE_KEY='<Private Key>'      VAPID_SUBJECT='mailto:<관리자 이메일>' PUSH_WEBHOOK_SECRET='<임의 문자열>'
   ```

3. SQL Editor 에서 트리거가 쓸 함수 주소와 같은 secret 을 Vault 에 넣는다.

   ```sql
   select vault.create_secret('https://<프로젝트 ref>.supabase.co/functions/v1/push', 'push_function_url');
   select vault.create_secret('<2번과 같은 PUSH_WEBHOOK_SECRET>', 'push_webhook_secret');
   ```

   바꿀 때는 `vault.update_secret((select id from vault.secrets where name = '...'), '<새 값>')`.

4. 관리자 계정으로 앱의 **설정 → 가입 신청 알림**을 켜고, 다른 브라우저(시크릿 창)에서 가입해 본다.
   알림이 안 오면 Dashboard > **Edge Functions > push > Logs**, SQL `select * from net._http_response order by created desc limit 5;` 를 본다.

- VAPID 키를 바꾸면 기존 구독으로는 보낼 수 없다. 관리자가 스위치를 다시 켜야 한다.
- 푸시 서비스 워커는 [web/push/sw.js](../../web/push/sw.js) 이고 scope `push/` 에 따로 등록한다.
  Flutter 의 `flutter_service_worker.js` 가 앱 경로에 등록됐다가 스스로 해제되므로, 같은 scope 를 쓰면 구독이 함께 지워진다.
- iPhone / iPad 는 홈 화면에 추가한 앱(standalone)에서만 웹 푸시를 받을 수 있다. (iOS 16.4+, [web/manifest.json](../../web/manifest.json) 의 `display: standalone`)

## 실행

```sh
flutter run -d chrome --dart-define-from-file=env.json           # 운영 서버
flutter run -d chrome --dart-define-from-file=env.staging.json   # 테스트 서버
```

VS Code 에서는 F5 의 **운영 서버 / 테스트 서버 (staging)** 구성으로 실행한다. ([.vscode/launch.json](../../.vscode/launch.json))
