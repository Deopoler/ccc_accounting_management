# 업무 규칙

화면과 서버가 따르는 규칙. 사용자에게 보이는 설명은 [사용법](../사용법.md) 참고.

## 교재 신청 회차

- 회차는 캠퍼스마다 `order_rounds` 에 저장되고 빈틈없이 이어진다. (다음 회차 시작 = 이전 회차 마감)
- **마감**: 기본은 매주 수요일 오전 9시 (KST). 캠퍼스 관리자가 **설정**에서 이번 회차의 마감 일시를 바꾸면
  다음 회차부터는 그 마감에서 1주일씩 이어진다.
- **회차 만들기**: 이번 회차가 마감되면 서버가 다음 회차(마감 + 7일)를 만든다. (`private.ensure_order_round`)
  신청이 없어도 지난 1년(52주) 회차는 항상 있다.
- **신청**: 신청 시점의 이번 회차(`round_id`)에 속한다. 신청 시점의 교재 가격이 `unit_price` 로 저장된다.
  `round_start` 는 이전 앱 호환용으로 남아 있고 트리거가 회차 시작 날짜로 채운다.
- **회원 수정 / 취소**: 마감 전 회차(이번 회차, 관리자가 옮긴 다음 회차)이고 상태가 **신청**이며 배송 전인 본인 신청만. (서버 RPC 에서 강제)
- **회차 이동**: 관리자는 선택한 신청을 신청 날짜와 상관없이 각자 자기 회차의 이전 / 다음 회차로 옮긴다. (`admin_shift_textbook_orders`)
  - 전부 옮기거나 하나도 옮기지 않는다.
  - 이번 회차의 다음 회차가 없으면 만든다. 그보다 뒤로는 옮길 수 없다.
  - 미리 만든 다음 회차는 이번 회차 마감을 바꾸면 함께 맞춰진다. (새 마감 ~ + 7일)
- **상태 흐름**: 신청 → 입금확인 (또는 취소), 배송 전 → 배송됨(관리자) → 수령 완료(회원 또는 관리자).
  배송을 해제하면 수령 기록도 지워진다. 취소된 신청은 배송 처리할 수 없다.
- **교재 도착 알림**: 관리자가 신청을 배송 처리(`is_shipped: false → true`)하면 해당 신청을 한 회원의 구독 기기로 웹 푸시 알림이 간다.
  한 번에 여러 신청을 일괄 배송 체크해도 회원마다 알림은 한 번만 간다. 일반 회원은 교재 도착 알림이 기본 켜짐(opt-out)이며 **내 신청** 화면에서 기기별로 끄거나 켤 수 있다.

## 데이터 보관 (1년)

용량 관리를 위해 캠퍼스에 새 회차가 만들어질 때(대략 매주) 그 캠퍼스의 1년 지난 데이터를 지운다. (`private.purge_old_campus_data`)

- 마감이 1년 넘게 지난 회차와 그 교재 신청(품목 포함)
- 마감일(없으면 만든 날)이 1년 넘게 지난 이벤트와 송금 기록
- 수신한 지 1년 넘게 지난 입금 내역(`bank_deposits`). 해석 실패(`unparsed`) 원문은 14일이 지나면 먼저 삭제된다.

지운 데이터는 되돌릴 수 없다. 관리자 사용법에 미리 CSV 로 내려받으라고 안내한다.

## 교재 카테고리

- 관리자가 카테고리를 만들고 순서(↑↓)를 정한다. 카테고리 안의 교재 순서도 ↑↓로 정한다. (새 교재는 맨 뒤)
  교재 추가 · 수정 창에서 카테고리를 고른다. 카테고리가 없으면 "기타".
- 회원은 카테고리 목록 → 카테고리 안의 교재 순으로 고른다. 주소는 `/textbooks?category=<id>`.
  여러 카테고리에서 고른 수량은 유지되며 하단 합계로 한 번에 신청한다. 카테고리 목록 화면에서 교재명 검색도 된다.
- 신청 가능한 교재가 없는 카테고리는 회원에게 보이지 않는다.
- 교재가 들어 있는 카테고리는 삭제할 수 없다. (교재를 다른 카테고리로 옮긴 뒤 삭제)

## 이벤트 송금

- 송금 대상은 관리자가 이벤트 화면의 **대상 추가**에서 직접 고른다. ("회원 전체 선택" 지원)
  이벤트 생성이나 회원 승인 시 자동 등록은 하지 않는다. 대상은 개별로 제외할 수 있다.
- **이벤트별 송금**: 회원은 미송금 이벤트마다 카드 안의 안내(금액 · 계좌 · 입금자명)대로 따로 송금한다. 여러 이벤트 합산 송금 안내는 하지 않는다.
- **입금자명**: 이벤트마다 관리자가 형식을 정한다. `{이름}`, `{학번}` 을 쓸 수 있고(예: `{이름}순여행` → `홍길동순여행`), 비우면 회원 이름.
  관리자 송금 현황과 미납자 CSV 에 회원별 입금자명이 나와 통장 내역과 대조할 수 있다.
- **개인별 금액**: 송금 현황의 회원 ⋮ > **금액 변경**으로 일부 회원의 금액만 바꿀 수 있다.
  비워 두면(= 기본 금액으로) 이벤트 금액을 따르며, 이벤트 금액을 나중에 바꿔도 조정된 회원의 금액은 유지된다.
  수금액 · 미수금 · 송금률 분모 금액, 회원의 미송금 합계, 미납자 CSV 모두 개인별 금액 기준이다.

## 자동 입금 확인

- **수집과 개인정보 필터**: 회계 담당자 휴대폰의 자동화 앱(안드로이드 MacroDroid 등)이 은행 알림 원문을 서버(`deposit-ingest`)로 보낸다.
  - 서버의 은행별 파서(현재 토스뱅크 지원)는 먼저 캠퍼스 **계좌 별칭**(`campus_deposit_settings.account_label`, 공백 제외 4자 이상, `토스뱅크`/`모임통장` 같은 일반 명칭 금지)이 알림에 들어 있는지 확인한다. 없으면 개인 계좌 알림으로 보고 원문을 저장하지 않은 채 `last_ignored_at` / `last_ignored_reason` / `ignored_count` 진단 정보만 갱신한다.
  - 계좌 별칭이 있는 알림에서는 구조적으로 명확한 출금 · 결제 · 광고(예: `<계좌 별칭> -> ...` 방향 화살표, 출금 제목/문구)만 무시한다. 금액은 읽혔지만 입금자명이 비어 있거나 `****`로 가려진 알림은 `unmatched` (`masked_depositor`, 금액 · 14일 원문 보관)로 저장해 자동 확인하지 않고 수동 연결 · 무시만 허용한다. 금액을 읽지 못한 알림은 모두 `unparsed`(해석 실패)로 14일간 원문을 보관한다.
  - 시간대가 없는 일반 날짜 문자열(`YYYY-MM-DD`, `YYYY/MM/DD`, `YYYY.MM.DD` + 시각)은 `Asia/Seoul(+09:00)`으로 해석하며, 알 수 없는 형식이나 누락된 타임스탬프는 서버 수신 시각으로 저장한다.
- **중복 방지**:
  - 정확한 재전송(`dedupe_key` 일치: `external_id + raw_hash`, 또는 동일한 `timestamp`를 함께 재전송해 `raw_hash + 초 단위 시각`이 일치)만 `duplicate`로 응답하고 원본 행의 `duplicate_count` / `last_duplicate_at`을 기록한다.
  - 서로 다른 `dedupe_key`이지만 같은 `raw_hash`가 60초 안에 다시 들어오면 버리지 않고 새 행을 저장하되 `ambiguous` (`possible_duplicate`, 원본 `duplicate_of_id` 기록)로 검토 목록에 보낸다. 중복 의심 행은 관리자가 **중복 아님**(`admin_clear_possible_duplicate`)으로 해제하기 전까지 재매칭이나 재해석으로 자동 확인되지 않으며, 수동 연결은 허용된다.
- **자동 매칭 규칙** (한 DB 트랜잭션 안에서 `textbook_orders -> event_payments -> bank_deposits` 순서로 잠그고 실행하며, 매칭 함수는 서브트랜잭션으로 감싸 예외 시 `unmatched` / `match_error`로 행을 보존하고 검토 푸시를 보낸다. 클라이언트는 `5xx` 응답 시 안전하게 재시도할 수 있다):
  - **교재 신청**: 승인된 활성 회원(`deactivated_at is null`)의 이름과 금액으로 매칭한다. 미납(`requested`) 단건 금액이 일치하거나, 같은 회원의 **같은 회차** 미납 유료 주문 2건 이상의 합계와 일치하면 함께 입금확인 처리한다. 서로 다른 회차 합산은 자동 확인하지 않는다.
  - **이벤트 송금**: 승인된 활성 회원의 `events.deposit_name` 형식(`{이름}`, `{학번}`, 비우면 회원 이름)으로 만든 예상 입금자명과 개인별 금액(`amount_override` 또는 `events.amount`)으로 매칭한다.
  - **입금자명 잘림**: 은행이 긴 이름을 자르는 경우를 고려해 정규화 후 **6자 이상**일 때만 앞부분 일치(prefix)를 허용하며, 후보가 정확히 1건일 때만 자동 확인한다.
  - **검토 목록으로 보내는 경우**: 후보가 0건(과 · 부족 입금, 신청 전 선입금, 비활성 회원의 미납), 후보가 2건 이상(같은 금액 주문 여럿, 교재와 이벤트 중복 일치), 같은 캠퍼스에 같은 입금자명을 만들 수 있는 승인된 동명이인(비활성 회원 포함)이 있는 경우(`same_name_members`, `{학번}`이 포함된 이벤트는 구분 가능하면 자동 확인).
- **기록과 취소 · 수동 처리**: 자동 확인되면 `textbook_orders.confirmed_deposit_id` / `event_payments.confirmed_deposit_id`에 연결 입금이 기록된다. 관리자는 **입금 내역**(서버 상태 필터 · 그룹별 건수 · 페이지네이션)에서 확인 취소(`admin_undo_deposit`), 중복 아님 확인(`admin_clear_possible_duplicate`), 대상 수동 연결(`admin_link_deposit_to_event` / `admin_link_deposit_to_orders`, 금액이 다르면 확인 후 명시적 허용 필요), 무시 / 해제, 재매칭, 해석 실패 재실행을 할 수 있다. 주문/이벤트 행이 삭제(DELETE)될 때는 입금 상태를 바꾸지 않고 연결만 해제한다.
- **웹 푸시 알림**: 자동 확인되면 해당 회원에게 확인 알림을 보낸다. 미매칭 · 후보 여럿 · 해석 실패 입금이 새로 들어오면 해당 캠퍼스 관리자에게 이름 · 금액을 뺀 알림을 보낸다.
- **보관 기간**: `unparsed` 및 이름 가려짐(`masked_depositor`) 원문(`raw_title`, `raw_text`, `raw_package`)은 수동 연결 · 재해석 · 무시 처리 즉시 지우며, 14일이 지나면 정리 작업 전이라도 조회 RPC(`admin_list_bank_deposits`)에서 숨기고 다음 정리 때 삭제한다. 입금 내역 전체는 기존 1년 정리에 포함된다.

## CSV 내보내기

- 교재 신청 현황: **신청 목록** / **교재별 집계** (화면의 회차 · 교재 · 상태 · 검색 필터가 적용된 결과)
- 이벤트 송금 현황: **미납자 CSV**
- UTF-8 BOM 을 붙여 Excel 에서 한글이 깨지지 않는다.
- 이름 등 사용자 입력값이 `= + - @` 로 시작하면 앞에 `'` 를 붙여 스프레드시트 수식 실행(CSV injection)을 막는다.
